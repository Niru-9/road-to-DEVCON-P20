Who In Here Can Help Me?
Kenji runs a builder community in Tokyo. Every member has an ENS name with a short profile: a bio, what they're good at, whether they have time to help. New members keep posting the same question in the group chat: "Is anyone here good at Rust and free to mentor this month?" Nobody can read three hundred profiles by hand, and the last chatbot someone tried confidently recommended a person who doesn't exist.

Kenji wants members to ask in plain language and get back real people from the community, with a reason for each, and an honest "nobody fits" when that's the truth.

What you'll learn

Building a retrieval index from live, user-controlled ENS data
Grounding a model's answer so it can only return people who really exist
Treating retrieved text as untrusted, because anyone can write anything in their bio
Measuring retrieval quality with recorded queries instead of eyeballing it
What to do

Seed a test community on Sepolia: at least 8 ENS names (ideally subnames of one parent) with profile text records. You decide which fields matter. Make at least one bio deliberately adversarial.
Build an index from those live ENS records, with a way to refresh it when profiles change.
Let a member ask a question in natural language and get back matching people, why each one matches, and their ENS name.
Handle the case where nobody matches.
Record a few example cases in the repo showing the same question answered under different preferences.
Record a set of test queries with the members you expect them to return.
Deliverable. A public GitHub repo containing the people-finder, the list of Sepolia names in your test community, and your recorded test queries.

Acceptance criteria

A new member asks who can mentor them in Rust this month and gets two real community members with a reason for each, or a straight answer that nobody fits.
8 scored test cases · 80 points are read straight off your code — open the Test cases tab to see exactly what they are before you build.

Test cases 
Each check is answered by reading the repo you submit — pass it, bank its points.

1.Every person in the answer is checked against the retrieved candidates

22
Passes if Code removes or rejects any person in the model's output who was not among the candidates retrieved for that query, before the answer is displayed.

Fails if The model's output is displayed without a membership check against the retrieved candidates, OR no model step exists.

2.Only a bounded number of candidates is sent to the model

10
Passes if An explicit limit (a top-k constant, slice, or score threshold) bounds how many profiles enter the prompt.

Fails if Every indexed profile is placed in the prompt regardless of the query, OR no retrieval step exists.

3.Profile text is never interpolated into the system prompt

12
Passes if The system/instruction message contains only app-authored text; profile content appears only in a separate user or data message.

Fails if Any profile text is inserted into the system/instruction message, OR instructions and profiles are concatenated into one undifferentiated prompt string, OR no model call exists.

4.The index is built from ENS text record reads

8
Passes if Profile content in the index is obtained from ENS text record reads.

Fails if Profile content comes only from hardcoded JSON, markdown, or pasted text, OR no index is built.

5.An empty match produces an explicit no-match response

8
Passes if A code branch returns an explicit no-match response when no valid candidates remain.

Fails if No such branch exists (an empty result still goes to the model or renders as a blank or error).

6.Recorded test queries state their expected members

8
Passes if At least one recorded query lists the specific member names it is expected to return, or explicitly expects no match.

Fails if No recorded queries exist, OR recorded queries state no expected members.

7.The model request has an explicit timeout

6
Passes if The model request is bounded by an explicit timeout.

Fails if The model request has no timeout, OR no model call exists.

8.No credential appears in any tracked file

6
Passes if No real credential, API key, private key, or authenticated URL appears in any tracked file.

Fails if Any real credential, API key, private key, or authenticated URL appears in any tracked file.
